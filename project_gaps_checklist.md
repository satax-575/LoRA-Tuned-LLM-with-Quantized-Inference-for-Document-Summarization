# 🚀 Project Gap Analysis — QLoRA Llama 3.1 8B Document Summarization

> Full audit of what's missing, weak, or unpolished before this becomes a **standout professional project**.

---

## Overall Verdict

The project has a **strong skeleton**: good module structure, a real FastAPI backend, Docker, Prometheus, Gradio UI, tests, and a Makefile. But there are critical gaps that separate it from a *truly professional* ML project — particularly around **reproducibility**, **CI/CD**, **observability completeness**, **missing code**, and **portfolio presentation**.

---

## 🔴 Critical — Blockers (Must Fix)

These will immediately raise red flags for any senior engineer or recruiter reviewing the repo.

### 1. Results Are Entirely Pre-Computed / Unverifiable
- [ ] The ROUGE scores (0.783 / 0.619 / 0.720) in `benchmark.py` and `demo/app.py` are **hardcoded constants** — `BENCHMARK_TARGETS` dict, not actually run
- [ ] `--report-only` mode just returns the same hardcoded dict with zero model inference
- [ ] **Fix**: Add a `outputs/benchmark/benchmark_report.json` with real or reproducible results, and clearly document it was produced by `make benchmark-live`. Consider committing the JSON file to git (it's small).
- [ ] **Fix**: Add a `RESULTS.md` or `results/` folder with: the training loss curve image, ROUGE table, ablation CSV — so reviewers can see proof without running the code.

### 2. No GitHub Actions / CI Pipeline
- [ ] `.github/workflows/` directory does not exist — zero CI
- [ ] No automated test runs on push/PR
- [ ] **Fix**: Add `ci.yml` workflow:  `pytest -m "not gpu"` on every push + `ruff` lint check
- [ ] **Fix**: Add a `badge` for CI status to `README.md`

### 3. `GITHUB/` Directory is Misplaced / Misnamed
- [ ] The `.gitignore` and `LICENSE` live inside a `GITHUB/` subdirectory — this is **non-standard** and will confuse every tool (GitHub won't auto-detect the license, `.gitignore` won't be picked up from a subdirectory)
- [ ] **Fix**: Move `.gitignore` and `LICENSE` to the **project root** where they belong

### 4. Missing `CHANGELOG.md`
- [ ] No version history. `pyproject.toml` has `version = "2.0.0"` but there's no changelog explaining what changed from v1
- [ ] **Fix**: Add a `CHANGELOG.md` using [Keep a Changelog](https://keepachangelog.com) format

### 5. Grafana Dashboards Not Included
- [ ] `docker-compose.yml` mounts `./grafana/provisioning` but **this directory doesn't exist** in the repo
- [ ] The entire observability story is broken — Grafana will fail to start
- [ ] **Fix**: Add `docker/grafana/provisioning/datasources/prometheus.yaml` and `docker/grafana/provisioning/dashboards/` with a pre-built dashboard JSON for the API metrics

## 🟠 High Priority — Gaps That Weaken the Portfolio Story

### 6. No Saved Training Artifacts / Evidence
- [ ] No `outputs/` folder, no training loss curve, no sample predictions file
- [ ] Anyone cloning the repo has no way to verify the results without a T4 GPU
- [ ] **Fix**: Commit a `results/` directory containing:
  - `training_loss_curve.png`
  - `rouge_benchmark.png` (the plot that `benchmark.py` generates)
  - `benchmark_report.json`
  - `ablation_results.csv` (from `training/ablation.py`)
  - `sample_predictions.jsonl` (5–10 example article → generated summary pairs)

### 7. Test Coverage is Shallow
- [ ] Only 4 tests in `test_api.py`, 0 edge-case tests for streaming, no integration test
- [ ] `test_training.py` and `test_summarizer.py` exist but haven't been reviewed — need GPU mocks
- [ ] No test for `data/preprocessing.py` or `data/dataset_builder.py`
- [ ] No test for `quantization/awq_quantize.py`
- [ ] `pytest --cov` never reported — no coverage badge or threshold enforced
- [ ] **Fix**: Add `tests/test_preprocessing.py`, cover the pure-Python logic without GPU
- [ ] **Fix**: Add `pytest-cov` minimum threshold (e.g. `--cov-fail-under=70`) to CI

### 8. `training/ablation.py` Has No Output Committed
- [ ] The ablation study (rank × LR grid) is a key technical differentiator but **no results are visible**
- [ ] The README table showing rank=4/8/16/32 is hardcoded, not generated by the script
- [ ] **Fix**: Run the ablation in `quick_mode=True`, save `outputs/ablation/ablation_results.csv`, and commit it
- [ ] **Fix**: Add a `results/ablation_heatmap.png` generated by the script

### 9. No Model Card / Hugging Face Hub Publishing
- [ ] Fine-tuned model not on HF Hub (even as a LoRA adapter, ~16MB)
- [ ] No `MODEL_CARD.md` documenting: dataset, hyperparams, eval results, intended use, limitations, biases
- [ ] **Fix**: Create `MODEL_CARD.md` following the [HF Model Card spec](https://huggingface.co/docs/hub/model-cards)
- [ ] **Fix**: Push the LoRA adapter to HuggingFace Hub so anyone can `from peft import PeftModel` and load it

### 10. Batch Endpoint Processes Sequentially
- [ ] `summarize_batch` in `inference/main.py` loops sequentially with `await summarizer.summarize()` — no concurrency
- [ ] vLLM's whole value is continuous batching; the batch endpoint defeats the purpose
- [ ] **Fix**: Use `asyncio.gather()` to submit all documents concurrently to the vLLM engine

### 11. No `CONTRIBUTING.md`
- [ ] No contribution guide, no coding style spec, no PR template
- [ ] **Fix**: Add `CONTRIBUTING.md` with: development setup, test command, code style (ruff), PR checklist
- [ ] **Fix**: Add `.github/PULL_REQUEST_TEMPLATE.md`

## 🟡 Medium Priority — Polish That Makes the Difference

### 12. `requirements.txt` Has No Pinned Versions
- [ ] All dependencies use `>=` (open bounds) — a fresh install in 6 months may break
- [ ] **Fix**: Add a `requirements-lock.txt` (or use `pip-compile`) with fully pinned versions for reproducibility
- [ ] Separate `requirements-dev.txt` for test-only deps (`pytest`, `pytest-cov`, `ruff`)

### 13. README is Missing Key Sections
- [ ] No **GIF/screenshot** of the Gradio demo or the Swagger UI — purely text
- [ ] No **"Quick Start (No GPU)"** section — the `--report-only` benchmark path exists but isn't highlighted
- [ ] No **"Known Limitations"** or **"Roadmap"** section
- [ ] Missing **citation block** (BibTeX for CNN/DailyMail, Llama 3.1 paper)
- [ ] No **"Results Evidence"** link (e.g. W&B run URL or HF Hub link)
- [ ] **Fix**: Add a demo GIF or screenshot as `assets/demo_screenshot.png` and embed in README
- [ ] **Fix**: Add `## Known Limitations` and `## Roadmap` sections

### 14. Streaming Endpoint Has No Tests
- [ ] `test_api.py` tests `/summarize` and `/summarize/batch` but **not `/summarize/stream`**
- [ ] SSE streaming is a key feature — it must be tested
- [ ] **Fix**: Add `test_streaming_endpoint()` using `httpx` SSE client or line-by-line response parsing

### 15. Auth Middleware Bypasses Health Endpoint Inconsistently
- [ ] `auth.py` middleware likely blocks all routes including `/health` — but `/health` is documented as "No auth required"
- [ ] Need to verify the excluded paths list in `APIKeyMiddleware`
- [ ] **Fix**: Audit `inference/auth.py` to ensure `/health`, `/docs`, `/redoc`, `/openapi.json` are on the allow-list

### 16. No `ruff` / `black` / `isort` Config
- [ ] `pyproject.toml` has no `[tool.ruff]` section
- [ ] Code style is not enforced — inconsistent across modules
- [ ] **Fix**: Add `[tool.ruff]` config to `pyproject.toml`, run `ruff check . --fix` once to clean up

### 17. `setup.py` is Redundant with `pyproject.toml`
- [ ] Both `setup.py` and `pyproject.toml` exist — modern Python only needs `pyproject.toml`
- [ ] **Fix**: Delete `setup.py`, move any remaining config into `pyproject.toml`

### 18. Shell Scripts Are Linux-Only, No Windows Note
- [ ] `scripts/run_training.sh`, `run_inference.sh`, `run_benchmark.sh` are bash scripts
- [ ] README mentions WSL2 but Makefile also uses bash (`if [ ! -f .env ]`) — no Windows path
- [ ] **Fix**: Add a note in README: "On Windows, use WSL2 or run the Python commands directly (see Makefile targets)"

### 19. `conftest.py` Fixtures Are Unused by Some Tests
- [ ] Root `conftest.py` defines shared fixtures, but `test_api.py` re-defines `mock_summarizer` locally — duplication
- [ ] **Fix**: Consolidate all shared fixtures into root `conftest.py`

### 20. Docker: `version: "3.9"` is Deprecated
- [ ] Compose file uses `version: "3.9"` — this key is [deprecated in Docker Compose v2](https://docs.docker.com/compose/compose-file/04-version-and-name/)
- [ ] **Fix**: Remove the `version:` key entirely (Docker Compose v2+ ignores it)
